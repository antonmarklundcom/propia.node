# D1 — inmobiliarios.com.py, the directory door

Phase D1 of `fable-plan-realtor-terreno-rental.md` (Stage 1 D, §5.2).
Branch `claude/d1-directory-door`. Landed 2026-09-10.

## What this phase actually changed

The directory door is **served** (`enabled: true`) and renders its own shell:
a seller-first home whose hero is a lead form, a three-step explainer, a
"cómo elegimos" section, a directory teaser, the "¿Sos inmobiliario?" band and
a short FAQ. It is not a narrowed marketplace — no search bar, no listing grid,
no `/publicar`, no login, no newsletter.

**DNS is the go-live switch, not the flag.** Nothing here reaches a visitor
until `inmobiliarios.com.py` points at Hostinger. `enabled: true` before that
is the `alquiler.com.py` precedent: `resolveVertical()` ignores a disabled
host, so a disabled door cannot be previewed with a `Host` header and
`verify:seo` would only ever check a synthetic copy of it.

### The ownership flag

`VerticalConfig.ownsDirectory` names which host is canonical for `/agentes`,
`/agente/*`, `/inmobiliarias` and `/inmobiliaria/*` — **per locale**, exactly
like `ownsListingDetail`, because a canonical from an English page to a Spanish
URL is one Google drops. It reads:

| Locale | Owner today | Why |
| --- | --- | --- |
| es | `inmobiliaria.com.py` | The directory door's DNS does not resolve yet, and a canonical pointing at a dead host is worse than a duplicate (plan §1 item 6). |
| en | `realestateinparaguay.com` | There is no English directory door; without this the English profiles would canonicalise into Spanish. |

`inmobiliarios.com.py` deliberately does **not** own them yet. Flipping it is
one line, in the go-live PR, after DNS — and `verify:seo` currently asserts the
flag is still off, so that flip is a deliberate edit rather than a drift.

Read by `origin.ts` (`directoryOwnerForLocale` / `directoryCanonicalOrigin` /
`hostOwnsDirectory`), `alternates.ts` (scope `"directory"`), `sitemap.ts`
(`includeDirectory`) and `verify:seo`.

A side effect worth naming: the rental doors used to submit agency and agent
profile URLs in their sitemaps, which they never owned. They no longer do.

### Marketplace routes off this door

Every marketplace page type 308s to `https://inmobiliaria.com.py<path>`.

This lives in **`middleware.ts`, not `next.config.ts`** — a deviation from the
plan's wording, and the reason is worth recording. `next.config.ts`'s
`has: [{ type: "host" }]` rules did not fire for this host in local testing,
while the rental family's identical rules did; rather than ship a redirect that
could not be demonstrated, it moved to the one place that has already resolved
the Host header to a vertical. The rule now reads
`marketplacePagesEnabled(vertical.key)` — the same predicate `sitemap.ts` reads,
so a visitor's redirect and the door's sitemap cannot disagree, and a door added
to the directory family later is covered without a second list of hosts.

Not redirected: `/admin`, `/agencia`, `/login`, `/registro` — staff and account
surfaces every host serves; they are simply absent from this door's chrome.

The target is the fixed constant `MARKETPLACE_PRIMARY_HOST`, not
`CANONICAL_HOST`: that one is inlined from `NEXT_PUBLIC_CANONICAL_HOST` at
build time, and a mis-set hPanel value would aim this door's whole marketplace
surface at nothing.

### Leads

A directory lead is the **existing** pipeline: `leadType: "seller"` plus
`utm.source` — `"directory:home"` or `"directory:profile"` — which is the
`/vender` marker pattern. No `leads.source` column, no new `lead_type` or
`routed_to` member, no schema at all.

`/api/leads` gained one optional field, `agentSlug`: zod-validated as a slug,
resolved to a real `agents` row, and only then routed `agent`. An unknown slug
falls through to `internal` and is **never** a 400 — a stale profile link must
not lose a lead. Because `leads` has no `agent_id` column, the resolved agent's
name and slug ride in `utm`, written from the row rather than from the
submitted string.

v1 matching is manual, on purpose: the operator picks up to three
professionals in `/admin/leads` and forwards with the WhatsApp button that is
already there. There is no agent supply to auto-match against yet, and that is
what lets this phase ship without a migration. The real structure is D3's
`lead_matches`.

### Derived zones

`listDirectoryZones()` (`src/lib/directory-queries.ts`) is the city filter on
the two index pages: cities that have published inventory owned by an agent or
an agency. Derived rather than stored because `agents` has no `zones` column
and this phase adds no schema — and it is the more honest signal anyway, since
a self-declared zone list says where somebody would *like* to work.

Cached with the **vertical key in the cache key** (CLAUDE.md's cross-door leak
rule) and tagged `listings`. That tag's writers were checked, not assumed:
every listing-writing action under `app/admin`, `app/agencia` and
`app/mis-avisos` calls `revalidateListings()`.

The home form's city select reads the full city list instead, deliberately: an
owner in a city where no professional works yet still has to be able to name
their city — that lead is exactly the one worth having.

### Never padded

`DirectoryHome` renders the recruiting band ("sé de los primeros") rather than
filler cards whenever there are fewer than three verified professionals with
live inventory (plan §1 item 7). A directory whose cards stand for nobody is
the failure of the site this door replaces, and it is invisible in a
screenshot — hence a constant in the component, not a judgement call.

## Verification

`npm run verify:local` green (typecheck, build, import, facets, i18n, seo).

`verify:seo` gained a "directory" block: exactly one owner per locale, every
served locale has one, the resolved owners are the two hosts above, the
directory door owns nothing yet, it is served, it claims no listing detail,
the marketplace's directory pages pair es↔en, a door that canonicalises them
away appears in no language map, the door's static sitemap list holds no
marketplace path, the redirect target is a real served door, and this door's
chrome has no login/publish/newsletter.

Checked against a dev server with `Host: inmobiliarios.com.py`:

- `/venta/asuncion`, `/propiedad/<slug>`, `/publicar`, `/precios`,
  `/proyectos`, `/planes`, `/para-inmobiliarias`, `/servicios` → **308** to
  `https://inmobiliaria.com.py<path>`; the same paths on `inmobiliaria.com.py`
  are untouched.
- `/para-inmobiliarios` → **200**, `<title>¿Sos inmobiliario? — Inmobiliarios
  Paraguay</title>`, directory nav and the "Encontrá tu inmobiliario" CTA, and
  zero occurrences of "Ingresar", `/publicar` or a newsletter block.
- The same path on `inmobiliaria.com.py` and `rentparaguay.com` → **307** to
  `/`.

**Not verified live, and why:** this environment has no MySQL, so `/`,
`/agentes`, `/agente/<slug>`, `/inmobiliarias` and `/sitemap.xml` return 500
with `ECONNREFUSED` on every door, marketplace ones included — the failure is
the database, not this branch. The same limit applies to the "a seller lead row
inserts with the marker" criterion. What stands in for it: the form posts the
same body shape as `VenderForm` to the same endpoint, the `agentSlug` →
`routedTo` resolution is a pure branch over a single indexed lookup, and the
`utm` marker is written server-side. **Worth one manual check against the live
database after merge** — submit the home form and confirm a `seller` row with
`utm.source = "directory:home"` in `/admin/leads`.

## Deferred to D1b

- **`/inmobiliaria/[slug]` directory rendering.** Its canonical, hreflang and
  robots follow `ownsDirectory` (the SEO half is done), but the page body is
  still the marketplace rendering. Unlike the agent profile it has no
  `agencySlug` lane in `/api/leads`, so a "contactá a esta inmobiliaria" form
  either needs one or should point at the home form — a small decision D1b
  should make rather than a guess made under time pressure here.
- **`/agente/[slug]` visual rendering** beyond its contact block: the header,
  coverage line and listing rail are still the marketplace's.
- Directory-specific CSS. Every surface reuses existing classes (`vd-*`,
  `mk-*`, `home-*`), so it is coherent but not yet its own look.
