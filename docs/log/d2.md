## What this phase actually changed

D1's own comment above `esDirectory` (`src/i18n/es.ts`) called it "the
skeleton… one real exemplar sentence each" for D2 to rewrite. Reading the
actual content: D1 had already written full, finished, vos-form copy for
every key — hero, form, the three-step explainer, "cómo elegimos", the
teaser and its empty state, the "¿Sos inmobiliario?" band, both list pages,
and a two-question FAQ with JSON-LD already wired on `DirectoryHome`. There
was no bare-skeleton pass left to redo. So D2's work was smaller than the
plan's estimate, and different in kind: review, extend, and fill the one gap
that was real.

1. **Fixed the stale comment.** The header above `esDirectory` claimed a
   skeleton-to-rewrite shape that did not match the code under it. Corrected,
   and added the reason there is no licence line: the founder's EAS/SERPLAID
   licence has not issued (plan §8), so it is omitted rather than stated as
   pending — the prompt's own copy rule.
2. **Extended the home FAQ** (`esDirectory.faq` / `enDirectory.faq`) from two
   to five questions each: how agents are chosen, what happens when nobody
   verified covers a zone yet, and that no exclusivity is required. Still zero
   invented figures — no counts, no response-time claim.
3. **Added `proFaq` / `proFaqTitle`** — a professional-facing FAQ, distinct
   questions from the owner-facing one above (cost, the inmobiliaria.com.py
   portfolio dependency, verification, how enquiries arrive). This is the one
   real gap D1 left: `/para-inmobiliarios` had a hero, bullets and the
   `agent_signup` form but no FAQ and no FAQ JSON-LD of its own — everything
   else the plan asked D2 to "fill" already existed.
4. **`app/para-inmobiliarios/page.tsx`** (directory branch, the only page this
   phase touches per its hard limits): renders `t.proFaq` in the existing
   `mk-faq` markup (same classes `/para-inmobiliarias` already uses — no new
   CSS) and adds `faqJsonLd(t.proFaq)` alongside the page's existing
   breadcrumb JSON-LD.
5. **Docs**: `README.md`'s domain section now names `inmobiliarios.com.py`
   next to the rental doors (it previously mentioned only the rental family
   as "merged but not live"). `CLAUDE.md`'s directory rows were already
   correct from D1's own commit — nothing to change there. This file and the
   plan's §9 index line.

## Verification

`npm run verify:i18n` — green, `es`/`en` shapes and arities match (checked
after both the FAQ extension and the new `proFaq` array).

`npx tsc --noEmit` — clean.

`npm run verify:local` — this environment has no MySQL, so the full pipeline
(`npm run build` included) could not be exercised end-to-end here in the
sense of hitting a live page; `typecheck` and the pure verifiers
(`verify:import`, `verify:facets`, `verify:i18n`) that do not need a database
were run directly and are green. `verify:seo` does not assert anything about
FAQ copy or count (checked by reading `scripts/verify-seo.ts`'s directory
block), so the FAQ additions carry no risk there.

**Not verified live, same reason D1 recorded:** no MySQL in this environment,
so `curl -H "Host: inmobiliarios.com.py"` against `/` and `/para-inmobiliarios`
could not be captured here. The change is copy plus two static arrays
rendered through the same components D1 already shipped and verified against
a dev server, so the risk is content-only, not structural. Worth a quick
manual check after merge: `/para-inmobiliarios` shows four new questions
under "Preguntas de inmobiliarios" and valid `FAQPage` JSON-LD in the page
source.
