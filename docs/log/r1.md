# R1 — rental "Services" header dropdown

Built the Services group's `links` in `SiteHeader.tsx`'s `rentalNav`: matched
the `d.rental.chromeNav` entry by `href === "/servicios"` (never by index —
`RentalServicesHub` already reads `chromeNav[1]` positionally) and mapped
`RENTAL_SERVICES` to `{ label: d.rental.services[s.dictKey].title, href:
"/servicios/<slug>" }`. Omitted `desc`: `services[dictKey].tagline` is a
full sentence written for the home-page cards, not the 3-5 word fragments
the marketplace panels use, and would blow out a 7-row panel.

Pure CSS dropdown, no new client JS — reused the existing
`.site-header__panel` styles (already theme-correct for the rental chrome,
no `globals.css` append needed). No new nav entries, no dictionary changes.

Verified: `npm run verify:local` green (typecheck, build,
verify:import/facets/i18n/seo). No local MySQL in this environment, so
checked rendered markup with `next start` + curl against `/contacto` (a
route with no listings query) on both `Host: rentparaguay.com` and `Host:
alquiler.com.py`: both show seven `site-header__panel-link`s under
Services, correct locale's labels, correct `/servicios/<slug>` hrefs. The
SSR payload confirms `MobileMenu` receives the same `nav` (all seven links
under the "Services"/"Servicios" group) — its existing `group.links.map()`
rendering was unchanged and already covered.
