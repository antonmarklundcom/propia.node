# R2 — English URLs for the rental business's own pages on rentparaguay.com

Anton reversed plan §1 item 8 ("Spanish slugs on both doors") for the rental
family's own pages, and confirmed the original WordPress `rentparaguay.com`
already published them under English paths — so the S1 redirect map points at
the new English slugs directly rather than hopping through the Spanish ones.

## What exists now

`RentalService` gained `slugEn` (`rent`, `airbnb-management`,
`apartment-management`, `realtor-asuncion`, `residency-paraguay`,
`invest-in-paraguay`, `virtual-address` — the last one spelled correctly, the
old site's `/virtual-adress/` is redirected to it). `dictKey` and `slug` are
unchanged, so the copy and the Spanish door moved nothing.

One helper spells every rental URL: `rentalPath(locale, page, service?)` over
`{services,about,contact} × {es,en}`, plus `rentalPathsByLocale()` for hreflang.
Read from `@/design/sections` everywhere in the app; **defined** in
`src/config/rental-services.ts`, which is deliberately import-free. That is not
tidiness — `next.config.ts` generates the 301s from the same helper, and Next's
config loader compiles that file outside the app's module graph, where the
`@/…` alias does not resolve (proved: importing it via `sections.ts` failed the
build with `Cannot find module './src/config/verticals'`). `sections.ts`
re-exports it so the phase's stated call sites are unchanged.

Routes: `app/services/page.tsx`, `app/services/[slug]/page.tsx`,
`app/about/page.tsx`, `app/contact/page.tsx`. Everything with a decision in it
(canonical, hreflang, breadcrumbs, the FAQ JSON-LD gate, the three "no"
answers) lives in `src/lib/rental-routes.tsx` and is called by both languages'
route files, so `/servicios` and `/services` cannot drift apart — the Spanish
route files shrank to ~15 lines each. `/nosotros` and `/contacto` keep their
marketplace half and gained one line: an English rental door 301s to `/about` /
`/contact`. `realestateinparaguay.com` is English but *marketplace*, so it is
explicitly not caught by that.

`languageAlternates()` needed no new parameter: `pathByLocale` already existed
as the documented hook for exactly this, unused. Its comment now says it is
used and why. Renaming it to the plan's `paths` would have been churn across a
file the whole SEO layer depends on.

Sitemap: `RENTAL_SITEMAP_PATHS` became `rentalSitemapPaths(locale)`. Each door
submits only the ten URLs it serves; the other language's ten are the ones it
301s away, and submitting a redirect is the same Search Console error as
submitting a URL you canonicalise elsewhere.

Redirects (`next.config.ts`) are now generated from `RENTAL_SERVICES` rather
than written out: the WordPress map retargeted to English slugs, and a
cross-language map on both hosts. `/services` and `/contact` were **removed**
from the WordPress map — they are real pages on the EN door now, and
redirecting them would be a loop.

## Verified

`npm run verify:local` green (typecheck, build, import, facets, i18n, seo).
`verify:seo` gained an R2 block (17 checks) driven through the same pure
helpers the app uses: each door's alternate is the path that door actually
serves, the two slug sets are disjoint so no redirect can target itself, each
sitemap excludes the other language's URLs and any `/propiedad`, and the
marketplace's own `/nosotros` hreflang is unchanged.

No local MySQL, so runtime checks used `next start` + curl on routes that run
no listing query (the same method R1 used). Seven `/services/<en>` URLs plus
`/services`, `/about`, `/contact` → **200** on `Host: rentparaguay.com`; all ten
Spanish twins → **308** to their English URL, one hop each. Exactly the reverse
on `Host: alquiler.com.py`. Both doors emit the same es/en/x-default trio with
the *different* paths, self-included. On `Host: inmobiliaria.com.py`,
`/airbnb-management` and `/about-us` 404 and `/services`, `/about`, `/contact`
redirect to `/` — the marketplace is untouched. The EN door's rendered chrome
(nav, R1's seven-item Services dropdown, footer) is entirely English paths.

`308`, not `301`: that is what Next's `permanent: true` emits, matching S1's
existing map. Google treats it as a permanent redirect.

## Notes / deferred

- The old WordPress URLs' **trailing-slash** forms take two hops
  (`/airbnb-management/` → `/airbnb-management` → `/services/airbnb-management`):
  Next's own trailing-slash normalisation runs before `redirects()`. This
  predates R2 — S1 had the same shape — and collapsing it needs
  `skipTrailingSlashRedirect`, which is app-wide. The bare forms are one hop.
- The sitemap could not be fetched (needs the database). Its content is proved
  statically instead, by the `verify:seo` checks above.
- `/propiedad/*` untouched on every door, as the phase required — it is the
  marketplace's page type. `/alquiler`, `/alquiler-temporal`, `/terminos` and
  `/privacidad` also stay Spanish-slugged on both rental doors: they are
  marketplace routes the rental doors render, not the rental business's own
  pages. An English `/terms` and `/privacy` would be a separate call.
- No schema change, no `/propiedad` change, no marketplace path or alternate
  change.
