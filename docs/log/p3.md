# P3 — directory profiles get the "Paso a Paso" look

Phase P3 of `fable-plan-polish.md`. Branch `claude/p3-profile-look`.

## Built

- New `.dir-profile` wrapper scopes every new rule to the directory branch
  (`isDirectory`) of `app/agente/[slug]/page.tsx` and
  `app/inmobiliaria/[slug]/page.tsx` — no override of the shared
  `agent-profile__*` / `agency-profile__*` classes the marketplace branch
  still uses.
- Header is now a white card: radius 16, the D4 shadow
  (`0 12px 40px rgba(26,29,43,.1)`), 96px round photo/initials (agencies keep
  a squared logo box, same distinction the old classes made), name in Lora
  via `--font-display`, meta line in Public Sans 15px
  `--color-ink-secondary`. The verified tick is now a small cobalt pill
  reading "Verificado" (`directory.listVerified`) instead of a bare ✓.
- Two columns from 960px: left = portfolio rail (+ "Equipo" on the agency
  page), right = the sticky `contact-panel` form. Below 960px both stack,
  form directly under the header, then the rail — matched by keeping that
  DOM order and placing the form's grid position with `grid-column` rather
  than reordering markup.
- Empty portfolio (`profileEmpty`) is now a quiet 1px hairline box, not the
  bare paragraph it was.
- One breadcrumb intermediate added on the directory branch only: Inicio ›
  Inmobiliarios (`/agente/[slug]`) or Inmobiliarias (`/inmobiliaria/[slug]`)
  › name, read from `directory.chromeNav[1]`/`[2]` — no new string. The same
  `crumbs` array feeds `breadcrumbJsonLd`, so the JSON-LD gets the same
  middle entry.
- No new i18n keys: every string on the restyled branch already existed
  (`profileKindAgent`, `profileCoverage`, `profileFormTitle`,
  `profilePortfolioTitle`, `profileEmpty`, `profileTeamTitle`,
  `listVerified`, `listListingCount`, `chromeNav`).

## Deviation from the letter of "owns the directory branch" (worth flagging)

The breadcrumb `<nav>` markup and the `crumbs` array it and the JSON-LD read
are built once, before the `isDirectory ? (...) : (...)` ternary — that is
how both page files were already structured. To add the directory-only
breadcrumb entry without duplicating the nav inside both ternary arms, both
were changed to iterate `crumbs` (built with a `dirCrumb` that is `null` on
every non-directory door). The output for `isDirectory === false` is
byte-identical to before (`dirCrumb` is `null`, so `crumbs` is unchanged),
and the marketplace JSX **inside** the ternary's `else` arm is untouched —
confirmed by `git diff origin/main` showing zero changes under the `) : (`
line in either file. Flagging this rather than silently calling the
marketplace branch "byte-identical file-wide", since two small blocks
outside the literal ternary did change.
