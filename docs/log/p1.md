# P1 — operation hubs: compact hero, listings first, chips for types

`app/[operacion]/page.tsx` reordered: hero (title, lead, search bar — tight,
`clamp(40px, 5vw, 64px)` padding, no min-height, `data-op={op}`) → latest
listings (cards, first) → by city → by type (last, thinnest section). The
count badge (`hub-hero__count`) is gone; its number moved into the latest
listings heading via `latestTitle(total)` — "Últimas publicaciones · N
avisos" / "Latest listings · N properties" — using the request's number
locale. `esHub.count`/`enHub.count` removed from both dictionaries (same
arity kept elsewhere).

Types render as `mk-chip` pills (existing class) with a small count badge,
and the whole section is hidden when fewer than 2 types have listings —
never one lonely tile.

`.search-bar__submit` now reads `--button-primary-bg` / `--button-primary-fg`
and hovers `--button-primary-bg-hover`, so the button follows each door's own
theme instead of a hardcoded marketplace color.

All CSS is in the `/* == P1 == */` block appended to the end of
`app/globals.css`; no existing rule rewritten in place.
