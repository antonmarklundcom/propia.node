# P4 — D3: agent zones + lead matching in /admin/leads

Schema phase. **Opened as a PR and not merged**: `agents` gains four columns
and `lead_matches` is a new table, so Anton runs `npm run db:status` before
and after `npm run db:migrate` (CLAUDE.md, "Migrations").

## What landed

- `agents.bio` (text), `license_no` (varchar 60), `years_active` (smallint
  unsigned), `zones` (json, array of ciudad **slugs**) — all nullable, so
  every existing row and every profile page renders exactly as before.
- `lead_matches` (`lead_id`, `agent_id`, `status`, `note`, `created_at`,
  `sent_at`) with `uq_lead_agent` and `idx_lead`. Migration generated by
  `npm run db:generate` → `drizzle/0013_ambitious_violations.sql`.
- `src/lib/matching.ts` (`server-only`): `suggestAgentsForLead()`,
  `rankCandidates()`, `proposeMatches()`, `markMatchSent()`.
- `listAgentMatchCandidates()` in `directory-queries.ts` — verified agents
  with both coverages, **uncached** (one admin click, never a public page).
- `/admin/leads`: a "Proponer inmobiliarios" panel on every `seller` lead
  whose `utm.source` starts with `directory:`, plus `esPanel.match*` keys.

## Decisions

- **Inventory outranks a declaration.** Ranking is zone+inventory, then
  inventory, then zone alone, cap 6 — a listing in the city is a fact, a
  `zones` list is an intention (the reason `listDirectoryZones` is derived).
- **The cap is on the write.** `MAX_MATCHES_PER_LEAD = 3` is enforced in the
  server action; checkboxes cannot be trusted to hold a product rule.
- **`sent` is recorded, never claimed.** The WhatsApp link is the delivery and
  a human clicks it; `markMatchSent` writes `sent_at` once, on that click.
  No email, no webhook, no fake "enviado".
- Re-saving a proposal is idempotent (`uq_lead_agent`), so it cannot reset a
  match already marked `sent`.

## Known issues / deferred

- **A directory lead carries no `utm.city`.** `DirectoryLeadForm` puts the
  city in the message body, and `/api/leads` is out of this phase's scope, so
  the zone signal is dark until one field is added there (D3b). Until then the
  panel says so and ranks by published inventory.
- **No agent-facing surface**: `accepted` / `declined` have no writer, and
  agents cannot edit `bio`/`zones` themselves — D3b.
- **`/admin/agentes` is not a profile editor** (it moves an agent between
  inmobiliarias), so nothing in this phase fills the new columns. Adding those
  fields there is D3b, and outside this phase's owned files.
- `esPanel` is Spanish-only staff copy and is not part of the bilingual
  `Dictionary`, so the new keys have no `en.ts` peer — `verify:i18n` agrees.
